# Room API 本机任务设计

## 意图

让 Agent Room 使用用户已配置的单个模型 API，在用户选定的本机目录完成基础开发任务。实现本地文件搜索、按需读取、经确认的修改与命令，以及根据测试输出继续修正的有限循环。不接入外部 CLI，不做多模型自动协作。

## 当前基础

- `agent_room_workspace.rs` 已管理现有模型配置、Windows 凭据、价格确认、每日调用/预算限制和取消状态。
- 现有聊天请求是单次文本请求，不发送工具定义，并拒绝模型返回的工具调用。
- 当前分支的 `agent_task.rs` 是 CLI 子进程实现；Room 任务卡已有选择目录、任务输入、停止、结果和草稿回填基础。

## 目标与边界

- 任务卡选择 Room 中已配置的具体模型、工作目录和任务说明；一个任务始终使用一个模型。界面区分“该服务商有工具调用协议”和“该具体模型已验证支持”；未经验证时明确标注，若 API 拒绝工具请求则显示原因，不执行工具、不切换模型。
- 模型可按需请求列目录、在所选目录内搜索文本、读取指定文本文件。仅将被请求的搜索片段或文件内容发送给当前模型；默认跳过 `.git`、`.env*`、密钥文件以及常见生成目录（如 `node_modules`、`target`、`dist`），不默认上传整个目录。
- 模型可提出文件修改。应用重新验证原文后展示修改前后内容；只有用户确认后才写入。
- 模型可提出命令。界面展示完整命令、工作目录、当前 Windows 用户权限提示，并明确说明退出码与命令输出会发送给当前模型；用户确认后才执行。命令结果使用有界输出回传，模型可据此继续；之后每次文件写入和命令仍须分别确认。
- 任务可停止；最终结果留在任务卡，可手动转入聊天草稿，不自动发送或触发其他模型。
- 命令的工作目录不构成系统隔离。运行的是当前 Windows 用户权限；界面必须明确显示。
- 复用 Room 的 API 凭据、付费开关、价格确认和每日调用/预算限制；每次 API 往返均计入限制，不自动重试，单任务最多 10 次模型往返。
- 对不支持原生工具调用的具体模型或端点明确报错，不通过提示词模拟工具调用，也不自动改用其他模型。
- 当前阶段不包含多 Agent、MCP、浏览器、后台自动化。

## 开源参考

- Cline 的官方工具清单包含文件读取、代码搜索、命令执行和编辑；其权限文档分别配置读、编辑和命令审批。本设计采用其基础“模型调用工具、工具结果回传、敏感操作审批”交互模式，并按 Room 现有 API、凭据与付费限制实现，不复制其扩展功能或代码：<https://github.com/cline/cline/blob/main/docs/tools-reference/all-cline-tools.mdx>、<https://github.com/cline/cline/blob/main/docs/sdk/guides/permission-handling.mdx>。
- OpenHands 的 Agent Canvas 展示了多后端和 Docker 沙箱等更大范围的控制台方案；这些会增加部署与权限架构，本阶段不纳入：<https://github.com/OpenHands/OpenHands>。

- 工具请求和结果往返遵循各家原生 API 结构，并保留助手工具调用响应的原始字段用于下一轮：<https://developers.openai.com/api/docs/guides/function-calling>、<https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview>、<https://ai.google.dev/gemini-api/docs/function-calling>、<https://docs.ollama.com/capabilities/tool-calling>。

## 考虑过的方式

1. 只读分析并生成建议：实现最轻，但不能完成用户要求的本地修改。
2. API 受限工具循环，文件修改预览确认、命令逐次确认、命令结果用于后续修正：保留基本开发能力，同时让用户控制写入和命令。本次选用此方式。
3. API 自动读写并运行命令：操作较少，但会在无人确认时执行，不符合用户选择。

## 界面与执行流程

任务卡显示 API 模型及工具调用验证状态、工作目录、任务说明和开始/停止状态。运行时展示目录搜索与读取进度；文件修改展示前后内容并提供“应用”或“拒绝”；命令展示完整命令、目录和权限说明，提供“运行”或“拒绝”。命令完成后展示退出码和有界输出，并回传给模型继续处理。任务结束后可将最终回复转入聊天草稿。

## 实现范围

- 在现有 Room API 适配层增加 provider 原生工具定义、回复解析和有上限的任务循环；普通 Room 聊天仍不提供工具。
- 只实现选定目录内的列目录、文本搜索、按需读取、修改提议和经批准的命令五种工具。
- 前端任务卡呈现搜索/读取进度、修改预览、命令审批及命令结果。
- 模拟测试不调用真实付费服务；真实 API 验收另行确认后进行。
- 沿用现有凭据与价格/预算控制，不新增 API 密钥或服务商。

## 验收

- 普通 Room 聊天仍不会调用本地工具或自动触发其他模型。
- 搜索和文件读取只返回所选目录内、有界且非敏感的文本；越界路径和凭据文件均不可读。
- 未经批准的文件修改和命令都不能执行；确认前后源文件变化时拒绝写入。
- 命令退出码与输出能回传给模型；模型可基于失败测试提出新修改或命令，且每项变更和命令仍需审批。
- 停止、失败不重试、单任务调用上限、每日预算、结果回填草稿均有针对性验证。
- 不支持原生工具调用的模型/端点会明确失败，不执行任何工具，也不切换模型。
